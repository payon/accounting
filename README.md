# Payon

소기업을 위한 복식부기 회계 웹앱입니다. 청구서를 발행하고, 지출을 기록하고, 은행 거래를 분류하고, 거래내역과 대조하고, 회계사가 기대하는 재무보고서를 뽑아낼 수 있습니다.

앱은 브라우저에서만 동작합니다. 로그인이나 별도의 서버가 없으며, 모든 데이터는 브라우저의 IndexedDB 데이터베이스에 저장되고 이 기기에만 존재합니다. 데이터를 다른 곳에 두려면 백업 파일로 내보내십시오.

## 주요 기능

- **매출**: 청구서, 견적서(청구서로 전환), 판매 전표, 매출 크레딧, 환불 전표, 그리고 하나 또는 여러 청구서에 적용되는 수금(미적용 크레딧 지원). 상태(미결, N일 후 만기, 연체, 부분 결제, 결제 완료)는 수금 내역과 만기일로부터 도출되며 저장하지 않습니다.
- **매입**: 지출, 수표, 지출결의서, 지출결의서 지불, 공급처 전체에서 한 번에 결제하는 화면, 매입 크레딧, 신용카드 환불, 발주서(지출결의서로 복사). 계정 줄과 품목 줄을 지원하며 줄별로 청구 대상 고객을 지정할 수 있습니다.
- **은행**: 거래내역 파일을 CSV(은행 종류 무관, 열 매핑 지원)나 OFX(.qfx, .qbo 포함)로 가져옵니다. 각 줄을 검토해 공급처/고객과 분류를 정해 추가하거나, 장부의 기존 거래(또는 미결 청구서·지출결의서 — 기록하면 결제로 처리됨)와 연결하거나, 이체로 기록하거나, 제외할 수 있습니다. 다시 가져오면 이미 가져온 줄은 건너뜁니다.
- **자동 분개 규칙**: 설명이나 금액 조건으로 줄을 자동 분류합니다. 유입/유출 방향, 계정별 조건, 우선순위, 바로 장부에 반영하는 옵션을 지원합니다.
- **계좌 대조**: 은행 거래내역의 최종 잔액에 맞춰 정리된 거래를 선택(체크)하고, 나중을 위해 저장하거나 조정 포함/제외로 마감할 수 있습니다. 대조 이력 확인, 마지막 대조 취소, 이후에 수정된 대조 거래의 불일치 보고서를 제공합니다.
- **계정과목표**: 표준 계정 유형, 하위 계정, 계정 번호, 기초 잔액, 비활성 계정, 그리고 잔액과 정리/대조 상태가 표시되는 계정별 거래 원장(레지스터).
- **기타 거래**: 예금(미입금자금에서 대기 중인 수금을 합쳐 입금, 기타 자금 추가, 현금 인출), 이체, 신용카드 결제, 반드시 균형이 맞아야 하는 일반 분개.
- **보고서**: 손익계산서(월/분기/년별, 전 월/전년 대비), 재무상태표(및 비교), 현금흐름표, 매출채권·매입채무 에이징(요약/상세), 미결 청구서, 미지급 지출결의서, 고객·공급처별 잔액, 고객별·품목별 매출, 공급처별 비용, 부가세 부채, 총계정원장, 시산표, 분개, 거래 목록, 계정 목록. 현금주의/발생주의 선택, 접을 수 있는 섹션, 금액 클릭으로 원거래까지 드릴다운, CSV 내보내기, 인쇄·PDF 저장 지원.
- **반복 거래**: 거의 모든 거래를 템플릿으로 만들어 일정에 따라 자동 생성하거나, 알림 목록에 띄워 사람이 확인후 생성할 수 있습니다.
- **부가세**: 세율 관리, 할인 후 과세 대상 줄에 대한 세금, 부채 보고서, 세금 결제 기록.
- **고객·공급처·품목**: 잔액과 거래 이력이 있는 상세 페이지, CSV 가져오기/내보내기.
- **마감일**: 특정 날짜까지 장부를 잠가 이미 마감한 기간을 수정하지 못하게 합니다.
- **검색**: 상단 바에서 번호·이름·금액으로 거래와 거래처, 계정, 보고서, 페이지를 찾습니다. `Ctrl+Alt` 키보드 단축키 지원(`?`를 누르면 목록 표시). 날짜 입력란은 `+`, `-`, `T`, `M`, `H`, `Y`, `R`, `W`, `K` 단축 키를 지원합니다.
- **첨부파일**: 모든 거래에 파일을 첨부할 수 있으며 이 기기에 저장됩니다.
- **감사 로그**로 최근 변경을 추적하고, **백업/복원**(파일로 다운로드)을 지원하며, 둘러볼 수 있는 **샘플 회사**와 다크·라이트·시스템 테마를 제공합니다.
- 데스크톱, 태블릿, 휴대폰에서 앱 같은 레이아웃 (하단 탭 바, 겹쳐 쌓인 항목, 카드형 목록).

## 스택

- 프레임워크 없는 바닐라 JavaScript 모듈. 개발·빌드는 [Vite](https://vitejs.dev), 아이콘은 [Lucide](https://lucide.dev), 테스트는 [Vitest](https://vitest.dev).
- 저장소는 브라우저의 IndexedDB(데이터베이스 이름 `payon`): 장부 데이터와 아직 전송 전 편집을 담는 아웃박스, 빠른 열기를 위한 캐시를 함께 둡니다.

### 성능

- 금액은 항상 정수 센트로 다루므로 합계가 정확합니다.
- 총계정원장은 컬럼 지향입니다: 전표(postings)를 날짜순으로 정렬해 `Int32Array`/`Float64Array` 컬럼에 담고, 계수 정렬로 계정별 인덱스를 만듭니다. 기간 보고서는 이진 탐색 두 번과 타이트한 루프 한 번으로 처리되고, 계정 레지스터는 자기 인덱스를 직접 읽습니다. 원장은 변경될 때 한 번, 요청이 있을 때만 지연 재구성됩니다.
- 파생 데이터(미결 잔액, 상태, 검색 인덱스, 잔액)는 스토어 버전별로 메모이즈됩니다.
- 긴 목록은 화면에 보이는 줄만 그리고(windowed tables), 차트는 기기 픽셀 비율로 캔버스에 그립니다.
- 홈 이외의 페이지와 거래 입력 폼은 처음 쓸 때 로딩됩니다. 첫 화면 자바스크립트는 gzip 기준 약 38 KB입니다.
- 거래 50,000건(전표 117,000개) 기준 Node에서 측정: 원장 구성 약 50 ms, 손익계산서·재무상태표 약 1 ms(월 58개 컬럼 포함), 매출채권 에이징 약 15 ms, 계정 레지스터 약 5 ms.

## 저장소 설계

- **레코드마다 작은 엔트리 하나**, 컬렉션별 키로 구분: `a:` 계정, `c:` 거래처, `i:` 품목, `t:` 거래, `b:` 은행 줄, `r:` 규칙, `p:` 반복 템플릿, `x:` 세율, `n:` 대조, 그리고 `settings`. 청구서 하나를 고치면 약 1 KB만 다시 씁니다.
- **인덱스 키 없음.** 한 회사의 장부는 메모리에 충분히 들어가므로 모든 조회(목록, 검색, 보고서)는 원장을 대상으로 로컬에서 실행됩니다.
- **쓰기는 먼저 아웃박스에.** 편집은 IndexedDB에 먼저 기록되고 배치(최대 100 엔트리)로 보내며, 오프라인에서도 편집이 사라지지 않고 연결이 돌아오면 보냅니다. 저장에 실패한 뒤 뒤따르는 편집이 막히지 않습니다.
- **대조 기록은 정리한 거래의 id와 금액만 저장**해서, 마감할 때 수백 건의 거래를 다시 쓰지 않고 이후 편집은 불일치로 나타납니다.
- **첨부파일은 데이터 레코드와 분리**해 `attachments/<거래 id>/` 형태의 키 아래에, 백업은 `backups/` 아래에 저장됩니다.

## 개발

```sh
npm install
npm run dev      # http://localhost:5181/
                 # http://localhost:5181/mock.html 은 인메모리 저장소 대역으로 동작
                 #   ?reset 을 붙이면 처음부터, ?env=app 은 임베디드 환경 모사
npm test
npm run build
```

`dev/viewports.html?path=home` 은 휴대폰과 태블릿 너비를 나란히 보여 줍니다.

## 테스트

`tests/`는 장부가 의존하는 로직을 다룹니다: 금액 파싱, 반올림과 정확한 비율 배분; 날짜와 이름 붙은 기간; 모든 거래 유형이 현금주의·발생주의 양쪽에서 균형 잡힌 전표를 만드는지; 미결 잔액, 적용, 취소와 삭제; 마감일; 모든 보고서(재무상태표 균형, 시산표 일치, 현금흐름과 은행 잔액 일치, 이익잉여금 연말 이월, 에이징 구간); CSV·OFX 거래내역 파싱과 중복 제거; 자동 분개 규칙, 매칭, 추천; 계좌 대조; 반복 일정; 검색; 검증; 백업과 복원; 샘플 회사; 그리고 아웃박스(오프라인 보류, 실패한 레코드가 뒤 편집을 막지 않음).
